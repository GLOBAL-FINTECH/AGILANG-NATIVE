# Native Language v0.8 production hardening

AGILANG Native already contains native implementations for arrays, strings, structs, enums, pattern matching, modules/imports, diagnostics, an LSP server, HTTP, crypto, databases, concurrency/runtime facilities and native C code generation. v0.8 hardening turns those capabilities into explicit release gates.

## Language semantics

The compiler is gated by executable tests for:
- arrays and bounds-checked indexing
- strings and literals
- structs/member access
- enums and exhaustive matching
- modules/imports
- typed assignment and return validation
- immutable assignment rejection
- loop control
- type aliases and cyclic-alias rejection

Generics, closures, and a first-class Result/error type remain language-design extensions; they are not represented as complete features merely by documentation.

## Native standard library

Existing native runtime/framework crates cover filesystem/platform, HTTP, cryptography, WebSocket/WebRTC, databases, process/platform integration and asynchronous execution. The v0.8 gate requires the complete workspace to compile and test together.

## Compiler quality

Release gates now include formatting, clippy with warnings denied, compatibility audit, full workspace tests, native-only validation, negative compiler tests, release compilation, runtime diagnostics and compile/run smoke tests. Build manifests record target and output metadata.

## Package manager

agilang-pkg provides deterministic agilang.toml parsing and agilang.lock generation/checking. Dependency sources can be registry, path or git/revision declarations. Lock entries are sorted and checksummed.

## Developer tooling

The repository contains an LSP server and VS Code grammar/project integration. A native REPL binary is now provided as agilang-repl; debugger launch configuration is included for C/C++ debugger adapters.

## Distribution

Tagged release CI builds Linux, Windows and macOS artifacts, emits SHA-256 checksums and publishes GitHub release artifacts. Release provenance attestation should be enabled for production tags.

## Important boundary

This release does not claim complete generics/closures/Result semantics or a mature public package registry. Those require language and ecosystem design work beyond a hardening gate. The goal is a truthful, testable native compiler/runtime baseline.
